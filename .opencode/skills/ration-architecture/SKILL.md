# Ration Architecture

pnpm + Turborepo monorepo. Node 22, pnpm (never npm/yarn). Everything is imported as TypeScript
source (`main: src/index.ts`) — no build step inside the workspace.

## Layout

| Path | Role |
| --- | --- |
| `apps/app` | Expo SDK app (Expo Router), one codebase for web/iOS/Android. See its own `AGENTS.md`. |
| `packages/core` | Pure TypeScript, no I/O: nutrients catalog, energy/macro math, intake tables, scoring. |
| `packages/ai` | OpenRouter client, PKCE sign-in, meal/label pipelines, coach. Depends on core. |
| `packages/garmin` | Read-only unofficial Garmin Connect client. |
| `tools/db-tests` | Vitest + PGlite database tests over the real migrations. |
| `tools/ui-smoke` | Playwright browser smoke tests + pure unit tests, mocked Supabase backend. |
| `tools/importer` | USDA FDC / Canadian Nutrient File loader. |
| `supabase/` | `migrations/` (plain SQL), `seed/` (generated), `functions/` (Deno edge functions + `_shared/`). |
| `scripts/` | Local device builds (`build-android-apk.sh`, `build-ios-ipa.sh`), icon generation. |
| `docs/` | `architecture.md`, `development.md`, `features.md` — read before non-trivial work. |

## Layering rule

**Anything with logic worth testing lives in `packages/core` or `packages/ai`; the app is thin glue
around them.** App code orchestrates; packages compute.

- Pure logic → `packages/core/src/*.ts` (see `energy.ts`, `resolve-targets.ts` for the house shape:
  pure functions, golden-value tests, formulas written in JSDoc).
- Data → React Query hooks in `apps/app/src/data/<area>.ts`, one file per area. Query keys follow
  `apps/app/src/data/keys.ts`: everything for one diary day lives under `['day', date, part]` via
  `dayKey()`; invalidate with `invalidateDay(qc, date)` — never invent parallel keys.
- Supabase client is a singleton in `apps/app/src/lib/supabase.ts`; QueryClient setup (staleTime,
  AsyncStorage persister, focus manager) in `apps/app/src/lib/query.ts`.
- UI → `apps/app/src/components/<area>/`; routes in `apps/app/src/app/` (every file there is a
  screen — keep non-route code out).
- Edge functions → thin `Deno.serve` wiring in `supabase/functions/<name>/index.ts`; ALL logic is
  pure in `supabase/functions/_shared/*.ts` with I/O injected and unit-tested. Edge code cannot
  import workspace packages — anything from core that edge functions need goes into the generated
  `supabase/functions/_shared/nutrient-map.generated.ts` (regenerate with
  `node --import tsx packages/core/scripts/generate-edge-nutrient-map.ts`; a db-tests test fails
  when stale). Deno imports use relative paths WITH the `.ts` extension.

## House comment style

The codebase is deliberately comment-rich — match it. Every module opens with a prose header
explaining what it is and WHY it is shaped that way. Large files use ASCII section dividers
(`// ------- Types`). JSDoc carries formulas inline. SQL and workflows get the same treatment.
Comments explain reasoning, not mechanics.

## Hard constraints (violating these breaks shipped builds)

- **Never create or edit `apps/app/android/` or `apps/app/ios/`** — Expo CNG: they are generated by
  `expo prebuild` and git-ignored. Configure native behavior in `app.json` / config plugins only.
- **Never run a bare local Gradle release build** — it OOMs even 15 GB machines. Local device
  builds go through `scripts/build-android-apk.sh` (laptop-safe `-Xmx2g`, 2 workers, `--no-daemon`)
  or the `Release` GitHub workflow. Releases are for the user to run, not the agent.
- **Never commit secrets**: `.env*`, keystores, pem/p8 files are git-ignored on purpose. The
  `SUPABASE_SERVICE_ROLE_KEY` never goes into the app or the repo.
- **Never edit an already-pushed migration.** New migrations (`supabase/migrations/`,
  `YYYYMMDDHHMMSS_name.sql`) must sort after the latest applied one, be idempotent, and get a test
  in `tools/db-tests`. Undoes are new files (see `…_drop_garmin_push.sql`).
- **Foods are immutable once logged** — updates go through `supersede_food` (SQLSTATE 23001).
- **Dependencies in the app**: `npx expo install <pkg>`, never `pnpm/npm add`. Expo ships breaking
  changes every SDK — check the SDK major in `apps/app/package.json` and read versioned docs
  instead of trusting training data.
- The importer is run as `pnpm --filter @ration/importer run import -- …` (bare `pnpm import` is a
  pnpm built-in).

## Commands

`pnpm typecheck` (all workspaces, turbo), `pnpm --filter @ration/app lint`, `pnpm test`.
Run lint + typecheck before declaring any task done. Conventional commits, one per feature/fix:
`feat(area): …`, `fix(area): …`.
